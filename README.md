# 👑 Commander OS — CEO Command Hub

**คุณคือ CEO** — บอร์ด C-level (CMO / CFO / COO / Researcher / Data Analyst) ไม่ได้มาเออออ
กับคุณ แต่มาถกกันเองจนได้ **ข้อเสนอที่ปกป้องได้** พร้อมความมั่นใจ แหล่งอ้างอิง และเสียงค้าน
ที่บันทึกไว้ — โดย **หยุดรอคำสั่งคุณก่อนทุก stage**

**แต่ละที่นั่งรันบนโมเดลคนละค่าย** (Claude Opus / Claude Fable / Gemini / GLM / DeepSeek)
เพราะ 5 persona บนโมเดลเดียวคือสมองเดียวสวม 5 หมวก — มันจะเห็นด้วยกันเองด้วยจุดบอด
เดียวกัน ระบบจึงวัดจำนวน provider ที่ต่างกันจริงและเตือนเมื่อบอร์ดเริ่มเป็น echo chamber

บอร์ดยืนอยู่บนข้อมูลจริงสองขา: **คลังเอกสารของคุณเอง** (LINE / อัพโหลด / Google Drive)
และ **หลักฐานที่แต่ละที่นั่งค้นมาเอง** — ไม่ใช่ความเห็นลอยๆ

## flow การประชุมบอร์ด — 6 stage (หน้า Boardroom)

เลือก **ขอบเขต** ที่จะถก + เปิด/ปิด **🌐 สืบข้อมูลจากอินเทอร์เน็ต** แล้วพิมพ์โจทย์ →
บอร์ดเดินทีละ stage และ **หยุดที่จุดตัดสินใจก่อนเข้า stage ถัดไปทุกครั้ง**

ขอบเขตเลือกได้ 3 แบบ:

| ตัวเลือก | บอร์ดอ่านอะไร |
|---|---|
| **ทุกโปรเจค** | เอกสารทั้งคลัง |
| **โปรเจคใดโปรเจคหนึ่ง** | เฉพาะเอกสารของโปรเจคนั้น |
| **ไม่อ้างอิงโปรเจคใด** | **ไม่ใช้เอกสารเลย** — สำหรับคำถามทั่วไปที่ไม่เกี่ยวกับธุรกิจของคุณ (ลากคลังเข้ามามีแต่จะทำให้คำตอบเอียงด้วยตัวเลขจากโจทย์อื่น) |

| Stage | ใครทำ | ได้อะไร |
|---|---|---|
| **1 · Frame** | Moderator | อ่านโจทย์แล้วบอกว่า *จริงๆ กำลังตัดสินใจอะไร* · **เลือกเฉพาะที่นั่งที่จำเป็น** (ไม่เกี่ยวไม่ต้องเรียก) · ระบุหลักฐานที่จะเปลี่ยนคำตอบได้ · เกณฑ์วัดว่าตัดสินใจถูก · **ตรวจกับมติเก่าแล้วเตือนเมื่อขัดกัน** |
| **2 · Independent Research** | ทุกที่นั่ง แยกกัน | **แต่ละที่นั่งตั้งคำค้นของตัวเอง ค้นเอง คัดกรองเอง** บนโมเดลของตัวเอง — ได้บรีฟ + แหล่ง `[n]` เป็นของใครของมัน (ค้นรวมกันแปลว่าแชร์จุดบอดกัน) |
| **3 · Opening Positions** | ทุกที่นั่ง | จุดยืนที่พร้อมปกป้อง + หลักฐานที่หนุน + ความเสี่ยงที่ซ่อนอยู่ + **สิ่งที่จะทำให้เปลี่ยนใจ** |
| **4 · The Debate** | ทุกที่นั่ง | โจมตี **หลักฐาน** ของกันและกัน (ไม่ใช่ท่าที) · ประกาศจุดที่หลักฐานขัดกัน · ยอมรับจุดที่ตัวเองพลาด |
| **5 · Red-team & Converge** | Red Team + ทุกที่นั่ง | Red Team โจมตี **การตั้งกรอบ** ไม่ใช่คำตอบ (บอร์ดกำลังตอบผิดข้อไหม / สมมติฐานร่วมที่ไม่มีใครตรวจ / มุมมองที่หายไป) · แต่ละที่นั่งบอกจุดอ่อนที่เหลือของตัวเองและ **ให้คะแนนความมั่นใจ %** |
| **6 · Defensible Brief** | ประธานบอร์ด | ข้อเสนอ + **ความมั่นใจ %** + ระดับความเห็นพ้อง + **เสียงค้านที่บันทึกไว้** + ประเด็นที่ CEO ต้องชี้ขาดเอง + 3 สิ่งที่ต้องทำใน 30 วัน + เงื่อนไขล้มเลิก — ออกเป็น **PDF บทสรุปผู้บริหาร** พร้อมทางเลือกให้กดตัดสินใจ |

**ที่จุดตัดสินใจแต่ละจุด คุณเลือกได้:**

- ▶ **ดำเนินการต่อ** — สั่งบอร์ดเพิ่มก่อนเข้า stage ก็ได้ (คำสั่งถูกยัดเข้า prompt ของ stage นั้นตรงๆ)
- ⏭ **ข้ามไป Defensible Brief เลย** — ไม่ต้องครบทุก stage
- ⏹ **STOP** — หยุดกลาง stage ได้จริง ผลที่ได้มาแล้วไม่หาย และกลับมาถกต่อได้
- ↩ **ย้อนกลับมาแก้จุดนี้ (reset)** — ลบ stage นั้นและถัดไปทิ้ง
- 🔀 **แตกกิ่งจากจุดนี้ (branch)** — เปิดไทม์ไลน์ใหม่ โดยของเดิมยังอยู่ครบ
- 📄 **PDF** — รายงานว่า stage นั้น "คิดด้วยอะไร"

> **บอร์ดเรียนรู้จากทางที่คุณปัดตก** — ทั้ง reset และ branch เก็บเส้นทางเดิมไว้ใน `history`
> แล้วป้อนกลับเข้า prompt ว่า "ห้ามเสนอซ้ำแนวเดิม ให้หามุมใหม่" คุณจึงเทียบสองทางเลือก
> จากจุดแยกเดียวกันได้เหมือน branch ใน git

## Persistent Memory — บอร์ดจำมติเก่าได้

เมื่อ Stage 6 จบ ระบบกลั่นการประชุมเป็นบันทึกถาวร: มติ · จุดยืน · ความมั่นใจ ·
**ข้อผูกมัดที่การตัดสินใจครั้งหน้าต้องเคารพ** · คำถามที่ยังไม่มีคำตอบ · สัญญาณที่ต้องกลับมาทบทวน

การประชุมครั้งถัดไปจะถูก **ตรวจกับบันทึกเหล่านี้ที่ Stage 1** ถ้าคำถามใหม่ขัดกับมติเก่า
ระบบจะขึ้นเตือนพร้อมบอกว่าขัดตรงไหนและรุนแรงแค่ไหน — บอร์ดที่กลับมติตัวเองเงียบๆ ทุกไตรมาส
แย่กว่าไม่มีบอร์ด ข้อผูกมัดจากมติเก่าจะถูกส่งเข้า prompt ของทุกที่นั่งด้วย

ดูและลบบันทึกได้ที่ `GET /api/memory` · `DELETE /api/memory/{id}` (แยกตามโปรเจคได้)

**เมื่อมติเก่ากลายเป็นของผิด** — หน้า Decisions มีปุ่มจัดการรายบันทึก:

- 🔀 **ถกใหม่อีกทาง** — เปิดการประชุมใหม่จากโจทย์เดิม พร้อมสั่งทิศทางที่อยากให้ไป
  (ของเดิมยังอยู่ครบ · branch ใน Boardroom แตกกิ่ง *ระดับ stage* ส่วนอันนี้เปิด *โจทย์* ใหม่ทั้งอัน)
- 🧠 **ลบการเรียนรู้** — ลบสิ่งที่บอร์ดเรียนจากการประชุมนั้น ไม่ให้ถูกใช้อ้างอิงหรือตรวจในครั้งถัดไป
  (บันทึกการตัดสินใจยังอยู่ — ให้คะแนน "พลาดจุดบอด" แล้วปล่อยมติเดิมไว้ในความจำ
  เท่ากับให้บอร์ดตรวจงานตัวเองด้วยคำแนะนำที่คุณปฏิเสธไปแล้ว)
- 🗑 **ลบบันทึก** — ลบการตัดสินใจทิ้ง เลือกได้ว่าจะเอาการเรียนรู้ไปด้วยหรือไม่

## ทำไม Researcher "ค้นไม่เจอ" ทั้งที่อินเทอร์เน็ตมีข้อมูล

เกือบทุกครั้งคำตอบคือ **ค้นไม่ได้ ไม่ใช่ไม่มีข้อมูล**

ถ้าไม่ได้ใส่ search key ระบบจะ fallback ไปใช้ DuckDuckGo แบบไม่มี key ซึ่ง**บล็อกคำขอ
อัตโนมัติบ่อยมาก** (ตอบ 403 / 429 หรือส่งหน้าตรวจบอทกลับมา) — บอร์ดจึงไม่มีหลักฐานให้อ่าน
แล้วรายงานตรงๆ ว่า "ไม่พบหลักฐาน" ซึ่งอ่านเหมือนว่าอินเทอร์เน็ตไม่มีข้อมูลเรื่องนั้น

**กดปุ่ม 🔎 ทดสอบการค้นเว็บ** ในหน้า Boardroom (หรือเรียก `GET /api/research/diagnose`)
จะยิงคำค้นจริง 1 ครั้งแล้วบอกตรงๆ ว่าค้นได้หรือถูกบล็อก พร้อมสาเหตุ

**วิธีแก้ถาวร** — ใส่ key ตัวใดตัวหนึ่งใน `hub/.env` แล้วรีสตาร์ท hub (ทั้งสองเจ้ามี free tier):

```bash
TAVILY_API_KEY=...     # tavily.com — ออกแบบมาให้ LLM ใช้ คืนเนื้อหาหน้าเว็บมาให้เลย
BRAVE_API_KEY=...      # brave.com/search/api
```

สิ่งที่ระบบทำให้แล้วเมื่อค้นไม่ได้:

- แยก **"ถูกบล็อก"** ออกจาก **"ค้นได้แต่ไม่เจอ"** ทั้งในการ์ดของแต่ละที่นั่งและในดัชนีหลักฐานรวม
- ลองทั้ง GET และ POST บนสอง endpoint ของ DuckDuckGo แล้ว **fallback ไป Mojeek**
  (คนละ index) ก่อนจะยอมแพ้
- เตือนในดัชนีหลักฐานรวมว่า *ข้อสรุปรอบนี้ยืนอยู่บนหลักฐานที่บางกว่าที่ควรเป็น*

## กัน Echo Chamber

`DEFAULT_PROVIDERS` ผูกแต่ละที่นั่งไว้กับ **โมเดลคนละค่าย** และหน้า Agents สลับได้ตลอด
ระบบคำนวณจำนวน provider ที่ต่างกันจริงแล้วเตือนเมื่อ:

- ทุกที่นั่งรันบน provider เดียวกัน → "สมองเดียวสวมหลายหมวก ไม่ใช่การถกเถียงจริง"
- ที่นั่งเยอะแต่ provider น้อย → "ยิ่งกระจายได้มาก จุดบอดร่วมยิ่งน้อย"

Red Team ก็ได้รับตัวเลขนี้ไปด้วย เพื่อประเมินว่าความมั่นใจของบอร์ดสูงเกินจริงหรือไม่

## รายงาน PDF

**ทุกรอบมีปุ่ม 📄 PDF** — ไม่ใช่แค่พิมพ์คำตอบออกมา แต่เป็น *หลักฐานว่าทำไมถึงเชื่อรอบนั้นได้*:
หลักการ/เฟรมเวิร์กที่แต่ละที่ปรึกษาใช้ · ตรรกะการให้เหตุผล · สมมติฐานและข้อจำกัดที่ยอมรับเอง ·
ตารางตัวเลขที่ถูกอ้าง · กราฟเปรียบเทียบ (เมื่อตัวเลขเทียบกันได้) · แหล่งอ้างอิงทั้งเว็บและเอกสาร

**Stage 6 มีปุ่ม 📑 บทสรุปสำหรับผู้บริหาร (.PDF)** เพิ่ม:

- **ความมั่นใจของบอร์ด %** + ตารางความมั่นใจรายที่นั่ง พร้อมบอกว่าโมเดลไหนอยู่หลังที่นั่งไหน
- **Red Team ฉบับเต็ม** — สิ่งที่โจมตีการตั้งกรอบ ยังอยู่ในเอกสาร ไม่ถูกกลบ
- ข้อสรุปของ C-level แต่ละคน *ในกรอบความเชี่ยวชาญของตัวเอง* + ความเสี่ยงที่แต่ละคนห่วงที่สุด
- **ทางเลือกในการตัดสินใจ 2-4 ทาง** พร้อมข้อดี/ข้อเสีย ใครหนุน-ใครค้าน ควรเลือกเมื่อไร ก้าวแรกใน 7 วัน
- **★ ทางที่บอร์ดแนะนำ** พร้อมเหตุผลชี้ขาด และประเด็นที่บอร์ดตกลงกันไม่ได้ (CEO ต้องชี้ขาดเอง)
- ช่องบันทึกการตัดสินใจสำหรับเซ็นบนกระดาษ

ทางเลือกชุดเดียวกันขึ้นเป็น **การ์ดกดเลือกได้ในหน้า Boardroom** — คลิกแล้วเติมช่องบันทึก
การตัดสินใจให้ทันที ต่อเข้าหน้า Decisions เพื่อวัดผลย้อนหลัง

> ตัวเลขในรายงานถอดจากสิ่งที่บอร์ดพูดจริงเท่านั้น — prompt สั่งห้ามแต่งตัวเลขเด็ดขาด
> ถ้าถอดไม่สำเร็จ (ไม่มี key / โมเดลคืนค่าไม่เป็น JSON) รายงานจะพิมพ์เฉพาะเนื้อหาที่เกิดขึ้นจริง
> พร้อมคำเตือน แทนที่จะเดาให้
>

## หน้าอื่น

- **⚖️ Decisions** — บันทึกว่าคุณตัดสินใจอย่างไร แล้วให้คะแนนย้อนหลังเมื่อรู้ผลจริง
  (กันความเสียหาย / เร็วขึ้น / เฉยๆ / พลาดจุดบอด) เพื่อวัดว่าที่ปรึกษามีค่าจริงไหม —
  แต่ละบันทึกมีปุ่ม **ถกใหม่อีกทาง / ลบการเรียนรู้ / ลบบันทึก**
- **📁 เอกสาร** — คลังความรู้: **อัพโหลดจากเว็บ (ลากวางได้)** / ส่งเข้า LINE bot /
  sync จาก Google Drive — บรรณารักษ์ AI จัดเข้าโปรเจคให้เอง (หรือคุณเลือกโปรเจคตอนอัพโหลด)
  · **ลบเอกสารที่เก่าหรือถูกแทนที่แล้วได้** (ลบออกจากคลัง + ลบไฟล์ในเครื่อง + ย้ายไฟล์
  ใน Drive ลงถังขยะ) — เอกสารที่ค้างอยู่หลังตัวเลขเปลี่ยนไปแล้ว จะคอยชี้นำคำแนะนำด้วยตัวเลข
  ที่ไม่มีใครเชื่อแล้ว
- **🤖 Agents** — เลือก AI provider ต่อที่ปรึกษา + ดูสถานะ service ของแต่ละแผนก (จุดเขียว/เทา)
